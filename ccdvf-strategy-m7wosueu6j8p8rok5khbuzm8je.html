Claude Certified Developer – Foundations（CCDV-F）に合格しました。市販の問題集も対策講座も無い新しい資格だったので、公式ガイドを一次情報として Claude に問題集を作らせ、それを解いて回すという方法を取りました。

ここに書く手順は CCDV-F 固有のものではなく、他の資格試験でもそのまま使えます。

Section 0前提（私の場合）

  • 本業は開発。エージェントの実装経験はそれほど多くない
  • Haiku / Sonnet / Opus を業務で使ったことがある
  • 業務を通じて「コンテキストをうまく扱わないと挙動がおかしくなる」という感覚は持っていた
  • Skill の作り方、CLAUDE.md の編集、それらがどのタイミングで読み込まれるかは分かっていた
  • MCP サーバーの連携方法（設定して繋ぐところ）は分かっていた
  • 事前知識としてはその程度

Developer 試験は、プロンプトの巧拙ではなくソフトウェアエンジニアリングの能力を測る試験だと感じています。

公式 Exam Guide の出題範囲を読むと、Claude 固有の知識だけで解ける部分はむしろ少数派です。大まかに3層に分かれます。

たとえば Context Engineering（3.8%）で問われるコンテキストの肥大やドリフトへの対処は、Claude に限らず LLM を使うなら共通の課題です。Agent Patterns and Frameworks（4.9%）に至っては、LangGraph や PydanticAI といった他社のフレームワーク名まで挙がっています。

※ この3層の分類は公式のものではなく、サブスキルの説明文を読んだ私の解釈です。割合も概算です。

Section 1中心にある考え方

教材を読むのではなく、教材を作らせて解く。

新しい資格には問題集がありません。しかし公式 Exam Guide の PDF には、出題範囲がサブスキル単位の配点付きで載っています。これを Claude に渡せば、配点どおりの問題を必要なだけ生成できます。

読むだけの学習と違って、どこを落とすかが数字で出るので、次に何をやるかを迷わずに決められます。

回すループ

公式PDF→ 配点どおりに問題を生成→ HTMLで解ける形に→ 解く→ 集計→ 弱点に絞って追加生成→ 復習ノート

生成・作り直し・解説の補強・英単語のまとめ・原則の抽出・復習ノートまで、すべて Claude に投げています。人間がやるのは「解く」と「不便なところを言う」だけです。

Section 2実際の手順

01

公式 PDF を一次情報にして問題を生成させる

Anthropic Partner Academy から公式 Exam Guide の PDF を入手し、Claude に読ませて問題を作らせました。

重要なのは、PDF にドメイン配点だけでなく「25個のサブスキル」の個別配点が載っていた点です。これに従って問題数を配分させることで、範囲の偏りが無くなります。

ドメイン名に騙されない

Model Selection というドメインは 16.8% ありますが、そのうち「Opus / Sonnet / Haiku の使い分け」は 2.7% しかありません。残りは LLM の基礎と SDK・HTTP の基礎です。サブスキルの粒度まで見ないと、ここを読み違えます。

02

Opus に作らせて、HTML の問題集として出力させる

Claude Desktop で Opus に依頼し、成果物を単体で動く HTML ファイル1枚として出力させました。

  • ブラウザで開くだけで動く。サーバーもネット接続も不要
  • 解答の記録がブラウザに保存され、続きから再開できる

「問題をテキストで列挙して」ではなく「解ける形の HTML にして」と頼むのが要点です。単なる文章より圧倒的に回しやすくなります。

03

使いながら機能を足していく

最初から完成形を作らせず、解いていて不便だと思った点をその都度直させました。

追加した機能理由
表は英語の設問と選択肢、裏は日本語訳と解説本番は英語のみ。英語で解き、日本語で確認する
解答後も設問文が消えないようにする正誤は色で分かる。英文と訳を同一画面で照合したい
ページ送りを画面下部に固定問題ごとに高さが変わり、ボタンが上下に動いていた
次の問題へ進むと自動でページ最上部に戻る長い解説を読んだ位置のまま次の設問が始まっていた
正誤の記録、誤答だけの絞り込み、復習フラグ弱点だけを回せるようにする
ドメイン別・形式別の正答率集計次に何をやるかを数字で決める
記録の書き出しと読み込み端末をまたいで持ち運ぶ

自分の学習動作に合わせて道具を変えられるのが、この方法の一番の利点です。

04

問題の質が悪ければ作り直させる

最初に生成された問題は知識確認型（用語や数値を直接問う形）に偏っていました。一方、公式ガイドに載っているサンプル問題は3問とも業務シナリオを提示して「最も適切な対応は？」を問う形でした。

そこでシナリオベースに作り直させました。生成された問題をそのまま信じず、公式サンプルと形を突き合わせる工程が要ります。

自分の集計でも、シナリオ型と知識確認型で正答率が大きく割れていたので、この2つを分けて記録したことが弱点の特定に直結しました。

05

解説が足りなければ公式ドキュメントを参照させて具体例を出させる

解説を読んで腑に落ちない問題は、公式ドキュメントを参照したうえで具体例を出すよう追加で依頼しました。

抽象的な説明だけでは覚えられませんが、実際のリクエスト JSON やコード片を見ると一度で入ります。ここは対話でしかできない部分で、既製の問題集に対する明確な優位点です。

06

分からない英単語はその場で聞き、まとめさせる

試験は英語のみです。読んでいて引っかかった単語や表現はその場で意味と使われ方を聞き、ある程度たまった時点でまとめのページを作らせました。

単語帳を買うのではなく、自分が実際に詰まった語だけが集まるので無駄がありません。

07

結果をもとに復習ノートを作らせる

解答記録を書き出して渡すと、Claude がどこを落としているかを集計し、復習ノートにまとめてくれます。

私の場合、落とした知識確認型の問題はたった9個の事実に集約されました。それを1ページにまとめてもらい、試験当日の朝はそれだけを読みました。

「どこが弱いか」を人間が探さなくていいのが効きます。

Section 3何に重きを置いたか

陳腐化しやすい技術やコードの詳細ではなく、全体を貫く原則。

パラメータ名や数値は仕様変更で変わりますし、覚えても応用が利きません。それより、範囲全体に繰り返し現れる考え方を押さえるほうが、初見の問題に対応できます。

ここも Claude にやらせた

公式ガイドの25サブスキルの説明文を読ませたうえで、「ここに繰り返し現れる設計思想をまとめて」と依頼しています。25項目を人間が読み比べて共通点を見つけるより速く、根拠となる記述も併せて示させれば裏取りもできます。

出てきたのは次の7つです。

  1. 強制力を持つのはモデルではなくコード プロンプトでの指示は保証になりません。モデルが出すのは「実行要求」であって実行ではないので、ガードレールも承認も、実際に動かす自分のコード側に置きます。
  2. 入ってくるものも、出ていくものも信頼しない ユーザー入力・検索結果・ツールの戻り値だけでなく、モデルの出力自体も検証対象です。形式が整っているほど正しく見えてしまうのが罠になります。
  3. 決定論が必要な場所を見極める 同じ入力が同じ出力を返さないのは仕様であって不具合ではありません。決定性は「文字列が一致すること」ではなく、検証と制約によって作ります。
  4. 再現性はバージョン管理から来る プロンプトとモデル ID は本番コードです。バージョンを固定し、何がどの構成で動いたかを記録して初めて、後から原因を追えます。
  5. コンテキストは容量ではなく品質 ウィンドウを広げるのは解決になりません。入れない・削る・隔離するの3つが手段です。
  6. 最小権限を、あらゆる軸で 権限だけでなく、渡すツール・入れるコンテキスト・発行する鍵のスコープすべてに効きます。最も強い制約は「そのツールを渡さないこと」です。
  7. 汎用ソフトウェア工学は免除されない AI アプリケーションであっても、まずソフトウェアとして正しいことが求められます。Section 0 の3層構造は、この原則の裏返しでもあります。

こうした原則は試験が終わっても業務で使えます。実際、合格そのものより、この整理ができたことのほうが価値がありました。

Section 46日間の流れ

日やったこと
1日目受験科目を決定。Claude に問題集の初版（HTML）を作らせる
2日目公開されているサンプル問題と形式を突き合わせ、シナリオ型に作り直させる
3日目通しで解く。ドメイン別・形式別に集計し、弱点に絞った問題を追加生成
4日目公式 Exam Guide PDF を入手。25サブスキルの配点どおりに問題を追加。複数選択形式にも対応させる
5日目通しで解く。英単語のまとめページと、原則の整理ページを作らせる
6日目通しで解く。結果をもとに直前チェック用の復習ノートを作らせる
7日目朝に復習ノートを通読。午後に受験 → 924 / 1000

最終的に問題数は 211 問になりました。平日は 30分〜1時間、直前の土日に集中という配分です。

なお受験形式は、自宅の環境設定が面倒だったのでテストセンターを選びました。オンライン監督（OnVUE）だと仮想マシンや VPN の制限、部屋のスキャンなど事前準備が必要になります。

Section 5他の資格でも使えるか

使えます。この方法が依存しているのは次の2つだけです。

  1. 公式の出題範囲（できれば配点付き）が公開されていること
  2. 公式のサンプル問題が数問でもあること（生成した問題の形を合わせる基準になる）

多くのベンダー資格はこの2つを公開しています。あとは冒頭のループを同じように回すだけです。

新しすぎて問題集が存在しない資格ほど、この方法の価値が上がります。

Section 6注意

守秘義務

試験内容には守秘義務（NDA）があります。受験前に同意を求められ、問題・選択肢・シナリオの開示は禁止されています。ここに書いたのは公開情報と学習方法だけで、実際の出題内容は含みません。

  • 生成された問題は本番の問題ではありません。あくまで範囲を網羅するための練習材料です
  • 資格の有効期限は12ヶ月。期限内なら Partner Academy の無料アセスメントで更新できます
  • 試験仕様は更新されます。受験前に公式 PDF の最新版で確認してください
